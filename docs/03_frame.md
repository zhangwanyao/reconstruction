# 03 第 1–2 步：读点云，定坐标系和底板

> 这两步要回答三个问题：**哪个方向是"上"？有没有底板？工件的长边朝哪？**
> 答案决定了后面所有计算用的坐标系。其中"有没有底板"判错是最致命的：z = 0 在哪、板底在哪、"缺口里看不看得到底板"全都会跟着错，分数会掉 20 分以上。

代码：`tools/proto_v2.py` 第 55–63 行调用；主体是 `tools/protolib.py` 第 97–228 行的 `detect_frame`。

## 第 1 步：读点云

`tools/read_any_pcd.py` 的 `read_xyz`（第 16–34 行）：

1. 一行一行读文字头，直到 `DATA` 那一行。`#` 开头的是注释。
2. 用头里的 `FIELDS`（字段名）、`SIZE`（每个字段几个字节）、`TYPE`（F 浮点 / U 无符号整数 / I 有符号整数）拼出一个 numpy 的结构化类型，然后：
   - `DATA binary`：数据是逐点存的（x y z x y z ……），直接 `np.frombuffer` 一次读完（第 26–27 行）。
   - `DATA binary_compressed`：先是两个 uint32（压缩后字节数、解压后字节数），后面是 LZF 压缩数据。解压后是**按字段存**的：先是全部点的 x，再是全部点的 y……（第 28–33 行）。
   - `DATA ascii`：不支持，直接报错（第 34 行）。
3. 只取 x、y、z，**马上转成 float64**。文件里是 float32，但现场坐标能到几千毫米、点有几百万个，用 float32 求和、求均值，误差会到毫米级。

LZF 是一种很简单的压缩格式（第 3–14 行），压缩数据由两种"指令"组成：

- 控制字节 < 32：后面跟着几个字节的原文，原样复制；
- 否则是"回引用"：从已经解压出来的内容里往前找一段，复制一遍（重复的内容只存一次）。

读完以后，`tools/proto_v2.py` 第 56 行把含 NaN / Inf 的点去掉（现有数据里其实没有，但有些设备会用 NaN 占位）。

## 第 2 步：定坐标系、判底板

`detect_frame(P, mode)` 分 6 小步。

### (1) 10 mm 网格顶面

给定一个"上方向" `up`，先建一个临时坐标系：`frame_from_up(up)`（第 97–99 行）造三根互相垂直的轴，第三根就是 `up`。把点转进去，`q = P·R0ᵀ`。

然后按 x、y 每 10 mm 分一格（`grid_top`，第 102–111 行）：

- 每格的**顶高** = 格里的点按高度排序后的第 95% 个（P95）。**为什么不用最高点？** 飞点（离群的噪声点）常常飘在表面上方，取最大值会被它拉高；P95 基本不受影响。
- **平整格**（`flat_cells`，第 114–125 行）：周围 8 个邻格都有点，而且顶高和每个邻格相差都 < 1.5 mm；另外本格至少 3 个点。平整格就是"一片水平面的中间部分"，板的边缘、斜面、噪声区都会被排除。

### (2) 精修上方向

传感器的 Z 不是真正的"上"：现场云的底板相对传感器倾斜了 0.23° ~ 1.31°，1 米就差 4 ~ 23 mm。后面判断"凸起"的门槛只有 8 mm，上方向不准，这个门槛就没意义了。

做法（第 134–142 行）：从传感器 +Z 出发，做 2 遍：

1. 算网格和平整格，取每个平整格的中心点（格中心的 x、y，加上顶高）。
2. 用 **RANSAC** 找点数最多的近水平平面（`_ransac_up`，第 70–94 行）：
   - RANSAC 是一种"抽签找共识"的拟合方法：随机取 3 个点定一个平面，数一数有多少点离这个平面 < 1.5 mm（这些叫"内点"）；重复 300 次，留内点最多的那个。离群点再多，也很难"抽中"，所以它不怕噪声。
   - 只接受法向和当前"上"夹角 ≤ 5° 的平面（我们要的是水平面，不是侧面）。
   - 最后用全部内点做一次最小二乘平面拟合（`fit_plane`，第 30–32 行：协方差矩阵最小特征值对应的特征向量就是法向），结果更精确。
3. 新的 `up` = 这个平面的法向（换回原坐标）。

最后记下 `up` 和传感器 Z 的夹角 `up_tilt_from_sensor_deg`。

### (3) 找水平层

用精修后的 `up` 重新算网格和平整格（第 143–156 行），然后统计平整格的顶高：

- 按 1 mm 一格做直方图，相邻 3 格平滑一下；
- 从最高的峰开始往下挑：峰高低于 max(30, 平整格数 × 1%) 就停；和已经挑中的层相差 > 6 mm 才收；
- 挑出来的层按高度从低到高排。

直方图上的一个峰 = 很多平整格在同一个高度 = 一个**水平层**（底板顶面、一组同高的立板顶面、抬高的平板……）。

### (4) 给每个层量指标

对每个层（第 157–182 行）：

| 指标 | 怎么算 | 用来干什么 |
|---|---|---|
| `area_m2` | 顶高和层高相差 < 2.5 mm 的格子数 × 100 mm² | 层有多大 |
| `solidity`（实心度） | 面积 ÷ 这些格子的凸包面积 | 是一整块板，还是稀稀拉拉的一堆条（立板顶面） |
| `hull_ratio`（凸包比） | 这层的凸包面积 ÷ 全部格子的凸包面积 | 是不是铺满了整个工件 |
| `far` | 这层的**足迹**（层的格子向外扩一圈）里，比层低 4 mm 以上的点占多少 | 底板下面应该没有点 |

注意 `far` 只看**足迹内**的点，不是全局：底板外面有什么，和"底板下面有没有点"无关。

**底面检测**：仿真云能"看穿"底板，底板下表面也有点，`far` 会很大。所以当 `far ≥ 0.03` 且下方点多于 200 个时，再看这些下方点的深度是不是集中在一个平行层里（第 172–180 行）：深度直方图的峰在 3 ~ 40 mm 之间、峰附近 ±3 mm 内的点超过 70%、覆盖了层面积的 30% 以上——满足的话，这就是底板的下表面，记下 `bottom_depth`，再算 `far_below_bottom`（比底面还低的点的比例）。

### (5) 判底板

第 183–190 行：

- **候选** = 从低往高数，第一个面积 ≥ 最大层面积 25% 的层（底板应该是"又低又大"的那个）。
- **有底板** ⇔ 有候选，并且（`far` < 0.03 或 `far_below_bottom` < 0.03），并且 `solidity` > 0.3，并且 `hull_ratio` > 0.3。
- 命令行 `--mode base` / `--mode nobase` 可以强制指定（`base` 模式下没有候选层时，还是按无底板处理）。

为什么这么判，看 3 个典型：

| 点云 | 情况 | 结果 |
|---|---|---|
| 现场云（F168 等） | 底板是最低的大平面，下面没有点（`far` ≤ 0.009） | 有底板 |
| SS30（仿真） | 底板下表面也扫到了，`far` = 0.214；但这些点集中在 11.5 mm 深的一层 | 有底板，顺便量出底板厚 |
| SS34（桁架） | 最低的层其实是腹杆顶面，实心度只有 0.09，下面还有大量点（`far` 0.585） | 无底板 |

### (6) 底板平面和工件坐标系

**有底板**（第 192–211 行）：

1. 取候选层的格子里、离层高 4 mm 以内的点（原坐标），太多就随机抽 40 万个。
2. 拟合**稳健平面**（`robust_plane`，第 35–42 行）：做 3 轮"最小二乘拟合 → 算每个点的残差 → 残差太大的点（> max(0.8 mm, 2.5 倍稳健标准差)）踢掉"，最后用剩下的点再拟合一次。
   - 为什么不直接最小二乘？飞点、焊缝、底板上的小东西会把平面拉歪。底板也不是理想平面：F455 的底板 4 m 长，平面残差 rms 有 1.22 mm。
   - 更不能拿"最低点"当 z = 0：一个飞点就把它拉低了。
   - "稳健标准差"用的是 1.4826 × 中位数绝对偏差（MAD），它不受少量离群点影响。
3. 如果检测到了底面：底板厚 `base_t` = 底面附近的点到平面的距离的中位数（第 206–210 行）。SS30 量出来是 10.14（参考 10）。量不到就用 `--base-t`（默认 20）。
   - 前面 (4) 里 SS30 的 `bottom_depth` 是 11.5，和 10.14 不一样：11.5 是从 10 mm 格的 P95 顶高往下数、按 1 mm 直方图得到的粗估，只用来圈出"底面附近的点"（±3 mm）；真正的厚度是这里用拟合出来的平面重新量的。
4. `ez` = 底板法向，原点 `o` 取在底板平面上。这样**底板顶面就是 z = 0**。

**无底板**：`ez` = 精修后的 `up`，`o` = 0。

**定 ex（工件长边方向）**（第 214–221 行）：把底板上的点（无底板时用全部点）投到水平面上，求**最小外接矩形**（`cv2.minAreaRect`），`ex` = 矩形长边方向，`ey = ez × ex`。这样工件在高度图里是"摆正"的，长边沿 x 轴。

最后 `Q = (P − o)·Eᵀ`（第 222 行）。无底板时再把 z 整体平移，让全部点 z 的 0.5% 分位等于 0（第 223–224 行），也就是工件最低处约为 z = 0。

> `ex` 的正负号（朝左还是朝右）取决于算法细节，对结果没有影响。

## 对答案：S1_tee

合成样例 S1 生成时，工件被转了 7°（绕竖直轴）、倾斜了 1.0°，噪声标准差 0.25 mm，底板 600 × 400 mm（见 `tools/synth_gen.py` 第 111–113 行）。看看 `out/S1_tee/parts.json` 里第 2 步量出了什么：

```json
 "up_tilt_from_sensor_deg": 1.0,
 "h_levels": [ { "z": -398.3, "area_m2": 0.239, "solidity": 0.92, "hull_ratio": 1.04, "far": 0.0 } ],
 "base_plane": { "n": [-0.0, -0.01745, 0.99985], "tilt_deg": 1.0, "rms": 0.248, "inliers": 399486 },
 "has_base": true,
 "frame": { "origin": [0.002, 6.963, -399.007], "ex": [0.99255, 0.12185, 0.00213], ... }
```

（上面为了好看压成了几行，文件里是展开的。）

- `up_tilt_from_sensor_deg` = 1.0：倾斜角找对了。
- `area_m2` = 0.239：底板 0.6 × 0.4 = 0.24 m²，减掉立板挡住的一点。
- `far` = 0.0：底板下面没有点，所以判成有底板。
- `hull_ratio` = 1.04，比 1 还大：这一层的凸包面积加了半圈周长做补偿（格子中心比真实外缘往里缩了半格），而分母"全部格子的凸包"没有加，所以铺满整个工件的底板会略大于 1。
- `rms` = 0.248：底板平面的残差正好等于生成时加的噪声 0.25 mm——平面拟合已经准到"只剩噪声"了。
- `ex` = (0.99255, 0.12185, …)：atan(0.12185 / 0.99255) ≈ 7.0°，转角也找对了。
- `h_levels` 里的 `z` 是在临时坐标系里量的（原点还没平移），所以是 −398 左右，不是 0。

## 小结

- 用"10 mm 网格顶面 + 平整格"把几百万个点压缩成几千个格子，后面的统计都很快。
- 上方向靠 RANSAC 找最大的水平面，精度到 0.01° 级。
- 有没有底板，看"最低的大层"下面有没有点；仿真云下面有点的话，再看这些点是不是正好是底板的下表面。
- 有底板时 z = 0 = 底板顶面；无底板时 z = 0 ≈ 工件最低处。
